# Review of all ten uploaded scripts

Reviewed actual file bytes recovered from the referenced conversation before writing replacements. Original SHA-256 hashes and syntax results are in `evidence/original_scripts.json`; original contents are retained as non-executable `.py.txt` references. The ten uploads use webcam index `0` by default, not a working explicit CSI/Argus pipeline. Commented CSI alternatives are not active behavior. CUDA selection is implicit in those ten scripts; the replacement makes it explicit.

## Additional local script: live_yolo_auto.py

Inspected `/home/sdp2026/YOLO_scripts/live_yolo_auto.py` (not one of the ten uploads). It already uses an explicit working CSI pipeline, validates CUDA, performs one prediction per frame, and checks writer initialization. The supplied log proves capture and model load succeeded before the MP4 writer failed. The OpenCV position-query warning occurred before successful frame delivery; it is not evidence of the recording failure's cause.

Its recording is compulsory by default; failing `mp4v` aborts the entire run. It rewrites the same output path and duplicates the newest frame in an unbounded catch-up loop to meet elapsed-time recording counts. A long delay can produce many repeated frames and extra stalls. No inference occurs during that catch-up loop. It also discards the first successfully read frame.

The provided replacement launcher defaults to `--record auto`; the central CLI defaults recording off. It preflights software encoders, falls back to MJPEG/AVI, makes optional recording failure nonfatal, uses unique outputs and exact received-frame timestamps, and removes the unbounded repetition loop. Explicit playback FPS is documented rather than claimed to be acquisition timing.

The exact missing encoder/caps behind the previous `cannot link elements` warning cannot be inferred from that log alone. Orin Nano has no NVENC hardware encoder, so replacing `mp4v` with a presumed hardware H.264 pipeline is not justified. [NVIDIA's Orin Nano software-encoding documentation](https://docs.nvidia.com/jetson/archives/r36.4/DeveloperGuide/SD/Multimedia/SoftwareEncodeInOrinNano.html) supports using software encoding. The new code requests OpenCV's FFmpeg backend explicitly and probes actual write/decode behavior.

## Important behavioral changes

No former movement launcher preserves steering/stop text. No launcher sends UART automatically. “No detections” is an explicit per-frame observation, not permission to drive. Default confidence is .25, adjustable with `--conf`; no distance or angle is guessed from box position. Live previews, recording, streaming, tracking and ROS can be combined without starting competing camera owners.
